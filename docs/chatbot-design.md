# au サービス案内チャットボット 設計メモ

場所: `/chatbot/` (GitHub Pages 公開後は `<サイトURL>/chatbot/` で閲覧)

## 要件(依頼内容)と対応状況

| 要件 | 対応 |
| --- | --- |
| au のサービスに特化したチャットボット | ✅ `chatbot/data/knowledge.js` の au 専用ナレッジベース(KB)から回答 |
| 回答には必ず出典元を記載 | ✅ KB の各項目が出典 URL を必須で持ち、回答に常に表示。出典のない回答は構造上生成されない |
| 曖昧な回答をしない・エビデンスがなければ憶測で答えない | ✅ KB に該当がない質問には「回答できません」と明示して出典なしの回答を拒否。未確認項目には警告バッジを表示 |
| 社内スタッフが誰でもアクセスできる | ⚠️ GitHub Pages は「全世界に公開」なので誰でも見られる=社内も全員アクセス可。ただし「社内**限定**」にしたい場合は別対応が必要(下記「要判断」) |
| 回答データを収集し、正誤判断後に次回回答へ反映 | ✅ 回答ごとの 👍/👎 フィードバックと未回答質問を収集(localStorage)。管理パネルで正誤確認 → 誤答は即時「回答停止」→ KB 修正 PR で恒久反映、のループ |
| 生成 AI の導入 | ⚠️ 静的サイトには安全に組み込めないため未導入。導入案を下記に設計済み(**要判断**: 課金・バックエンドが必要) |

## アーキテクチャ(現状)

```
[スタッフ] ─ 質問 → chatbot.js(キーワード検索)─ 照合 → data/knowledge.js(KB)
                │                                        ↑
                ├ 一致あり → 回答+出典+確認日+正誤ボタン    │ PR で修正(恒久反映)
                ├ 一致なし → 「回答できません」+未回答として記録 │
                └ フィードバック → localStorage → 管理パネルで正誤判断
                                     ├ 誤答 → 「回答停止」(即時反映)
                                     └ エクスポート(JSON)→ Issue/PR で KB 更新
```

- 静的サイト(HTML/CSS/JS のみ、外部 CDN なし)というリポジトリ規約の範囲内で実装
- 「憶測で回答しない」はプロンプト頼みではなく**仕組みで保証**:回答の材料が
  出典付き KB しか存在しないため、根拠のない文章は出力されない

## ナレッジベースの運用ルール

1. 追加・修正はすべて `chatbot/data/knowledge.js` への PR で行う
2. スタッフが出典 URL を実際に開いて内容を確認したら `verified: true` にし、
   `lastVerified` に確認日(YYYY-MM-DD)を書く
3. `verified: false` の項目は回答時に「スタッフ未確認」バッジが付く
4. 誤りの報告があったら: 管理パネルで「回答を停止」(即時)→ KB を直す PR(恒久)
5. 未回答質問のログを見て、需要のある項目から KB に追加していく

初期データ 8 件はすべて `verified: false`(スタッフ確認待ち)で登録している。
電話番号など具体的な数値・条件は、必ず出典で確認してから `verified: true` にすること。

## フィードバックデータの注意

- 収集データは各利用者のブラウザの localStorage に保存される(サーバー送信なし)
- そのため集計はブラウザ単位。全社集計したい場合は、管理パネルの
  「エクスポート(JSON)」でファイルを出し、Issue に添付して集約する運用とする
- サーバーへの自動集約をしたい場合はバックエンドが必要(下記「要判断」)

## 生成 AI(Claude API)導入案 — 要判断

「生成 AI を導入したい」という要望への設計。**今回は実装していない**。理由:

1. **API キーの安全性**: 静的サイト(GitHub Pages)に API キーを置くと全世界に漏洩し、
   第三者に課金を悪用される。生成 AI の呼び出しには必ずバックエンド(中継サーバー)が必要
2. **課金の発生**: API 利用は従量課金。本社ルール上、課金が発生する操作は経営者の承認が必要

### 導入する場合の構成案

```
[スタッフ] → 静的サイト(本リポジトリ) → 中継バックエンド(要新設) → Claude API
                                          │ APIキーはここに保管
                                          │ KB を根拠として渡す(RAG)
                                          │ 「KB にない内容は回答しない」と
                                          │  出典必須をシステムプロンプトで強制
                                          └ 質問・回答・フィードバックをログ集約
```

- バックエンド候補: Cloudflare Workers / Google Apps Script など(無料枠あり、ただし API 利用料は別)
- 生成 AI 化しても「出典必須・憶測禁止」の要件は、KB を根拠に回答させる
  RAG 構成+システムプロンプトで維持する(KB 外の質問は現在と同じく回答拒否)
- 利点: キーワード一致では拾えない言い回しの質問にも、KB の範囲内で柔軟に回答できる

### 社内限定アクセスにする場合 — 要判断

GitHub Pages には閲覧制限機能がない(公開のみ)。社内限定にするなら:

- 案 A: Cloudflare Access 等の認証付きホスティングへ移行(無料枠あり)
- 案 B: GitHub の private リポジトリ + GitHub Pages(有料プランが必要)
- 案 C: 「URL を社内にだけ共有する」運用で妥協(技術的な制限はなし)← 現状はこれ

## 確認方法

1. ブラウザで `chatbot/index.html` を開く(公開後は `<サイトURL>/chatbot/`)
2. 「auの問い合わせ電話番号は?」→ 出典リンク付きの回答が出ること
3. 「今日の天気は?」→ 出典なしで憶測回答せず「回答できません」となり、
   管理パネルの「未回答だった質問」に記録されること
4. 回答の 👎 を押す → 管理パネルに誤り報告が集計されること
5. 管理パネルで「回答を停止」→ チャットで同じ質問をすると回答されなくなること
6. 「収集データをエクスポート」→ JSON がダウンロードされること
