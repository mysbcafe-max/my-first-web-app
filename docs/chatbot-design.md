# au サービス案内チャットボット 設計メモ

公開先: Cloudflare Pages(Cloudflare Access で社内スタッフのみ)
セットアップ手順: [cloudflare-setup.md](./cloudflare-setup.md)

## 要件(依頼内容)と対応状況

| 要件 | 対応 |
| --- | --- |
| au のサービスに特化したチャットボット | ✅ `chatbot/data/knowledge.js` の au 専用ナレッジベース(KB)から回答 |
| 生成AIの導入 | ✅ Cloudflare Pages Functions 経由で Claude API を呼び出し。APIキーはサーバー側のみ |
| 回答には必ず出典元を記載 | ✅ 出典URLはサーバーがKBから引く。**モデルには出典URLを渡していない**ため作文が構造的に不可能 |
| 曖昧な回答をしない・エビデンスがなければ憶測で答えない | ✅ 根拠となるKB項目のidが返らない回答はサーバーが強制的に「回答できません」に倒す |
| 社内スタッフが誰でもアクセスできる | ✅ Cloudflare Access のメール認証(50人まで無料)。許可リストで管理、退職者は個別に取り消し可能 |
| 回答データを収集し、正誤判断後に次回回答へ反映 | ✅ 全社共通のD1データベースに集約。誤答は「回答停止」で全社に即時反映、恒久修正はKBのPR |

## アーキテクチャ

```
[社内スタッフ]
      │  ① Cloudflare Access がメール認証(許可リスト外は到達不可)
      ▼
[Cloudflare Pages]  ← 同一オリジンなので /api/* も同じ認証で保護される
      │
      ├─ chatbot/          静的フロントエンド
      │      │ ② 質問を POST /api/chat
      │      ▼
      └─ functions/api/    サーバー側(ブラウザに配信されない)
             ├─ chat.js      ③ KB本文 + 厳格なシステムプロンプトで Claude API を呼ぶ
             │               ④ モデルは「根拠にした項目のid」を返す(URLは返さない)
             │               ⑤ サーバーが id を実データと突き合わせ、出典URLを付与
             │                  → 有効なidが0件なら「回答できません」に強制
             ├─ feedback.js  正誤フィードバック / 未回答質問を D1 に記録
             └─ admin.js     全社集計の取得・誤答項目の回答停止
                    │
                    ▼
            [Cloudflare D1] feedback / unanswered / disabled_entries
```

**ANTHROPIC_API_KEY は `functions/` 内でしか読まれず、ブラウザには一切届きません。**

## 「憶測しない・出典必須」を仕組みで保証している3点

プロンプトでの指示だけに頼らず、サーバー側のコードで担保しています。

1. **モデルに出典URLを渡さない** — `buildKnowledgeContext()` はKBの本文と id だけを渡します。モデルはURLを知らないので、それらしいURLを作文できません
2. **出典はサーバーが id から引く** — モデルが返した `source_ids` を実データと突き合わせ、実在する項目の出典だけを回答に付けます
3. **根拠ゼロの回答を通さない** — モデルが `answerable: true` と主張しても、有効な id が0件なら回答を破棄し「回答できません」に置き換えます

さらに構造化出力(`output_config.format`)でレスポンス形式をスキーマ強制しているため、パース失敗による予期しない挙動も防いでいます。

## 2つの回答経路(フォールバック設計)

| 経路 | 使われる場面 | 特徴 |
| --- | --- | --- |
| ① 生成AI(`/api/chat`) | Cloudflare 上で稼働中 | 言い回しの揺れに強い。画面右上に「生成AI 回答モード」と表示 |
| ② キーワード検索 | API未設定・セットアップ途中・ローカル確認時 | KBを直接照合。「キーワード検索モード」と表示 |

どちらの経路でも出典必須・憶測禁止は共通です。セットアップが完了していなくてもサイトは壊れません。

## ナレッジベースの運用ルール

`chatbot/data/knowledge.js` が唯一の情報源で、生成AIとキーワード検索の両方が同じファイルを読みます(更新箇所は1つだけ)。

1. 追加・修正はすべて PR で行う。main にマージすると Cloudflare Pages が自動で再デプロイ
2. スタッフが出典URLを実際に開いて確認したら `verified: true` にし、`lastVerified` に確認日(YYYY-MM-DD)を記入
3. `verified: false` の項目は回答時に「スタッフ未確認」バッジが付く
4. 誤りの報告があったら: 管理パネルで「回答を停止」(全社に即時反映)→ KBを直すPR(恒久修正)
5. 未回答質問のログを見て、需要のある項目から追加していく

**初期データ8件はすべて `verified: false`(スタッフ確認待ち)です。** 電話番号など具体的な数値・条件は、必ず出典で確認してから `verified: true` にしてください。

## コストとモデル選択

`CLAUDE_MODEL` 環境変数で切り替えます(既定 `claude-haiku-4-5`)。

| モデル | 入力 / 出力(100万トークン) | 1問あたり目安 | 月1,000問 |
| --- | --- | --- | --- |
| `claude-haiku-4-5`(既定) | $1 / $5 | 約1円 | 約1,100円 |
| `claude-sonnet-5` | $3 / $15 | 約3円 | 約3,200円 |

- Anthropic コンソールで**月額上限**を設定しているため、請求が青天井になることはありません
- プロンプトキャッシュは設定済みですが、**現在のKBサイズでは未だ効きません**。Haiku 4.5 のキャッシュ最小サイズ(約4,096トークン)をKBが超えると自動的に効き始め、入力コストが下がります

## 確認方法

ESモジュールを使っているため、ローカル確認にはHTTPサーバーが必要です(`file://` では動きません)。

```sh
cd my-first-web-app && python3 -m http.server 8000
# → http://localhost:8000/chatbot/ を開く(APIなしのためキーワード検索モードで動作)
```

Cloudflare へデプロイ後の確認項目は [cloudflare-setup.md](./cloudflare-setup.md#動作確認) を参照。

1. 「auの問い合わせ電話番号は?」→ 出典リンク付きの回答が出る
2. 「今日の天気は?」→ 憶測せず「回答できません」となり、未回答質問に記録される
3. 👎 を押す → 管理パネルに誤り報告が集計される
4. 管理パネルで「回答を停止」→ 別のブラウザでも同じ質問に回答されなくなる(全社反映)

## 残っている検討事項

- **Cloudflare Access の無料枠は50ユーザーまで。** 51人目はアクセス不可になります(自動課金はされない)。超える場合は $7/人/月 への移行が必要
- **ナレッジベース初期8件の内容確認**(出典URLを開いて `verified: true` にする作業)の担当者が未定
