## シフト自動生成ツール(複数店舗)

https://mysbcafe-max.github.io/my-first-web-app/shift/

登録した社員情報(住所・レベル・NG店舗・勤務可能曜日・希望休・週上限)と店舗情報(必要人数・必要レベル・リーダー要件・営業日)から、期間内の各日の店舗アサイン表を作ります。**どの店舗に誰を出すか**を決めるためのツールです。

- データはブラウザ内(localStorage)にだけ保存され、外部サービスには送信しません(費用ゼロ)
- 住所は都道府県・市区町村から距離を推定します。緯度・経度を入れると実距離で計算します
- 結果は CSV(表形式・一覧)で書き出し、印刷もできます
- 「データ」タブのサンプルで動作を試せます

ファイル構成:

| ファイル | 役割 |
|---|---|
| `shift/index.html` | 画面 |
| `shift/style.css` | スタイル |
| `shift/app.js` | 画面の処理(保存・フォーム・結果表示) |
| `shift/scheduler.js` | 生成ロジック(UI に依存しない) |
| `shift/test/` | ロジックのテスト(`node --test "shift/test/*.test.js"`) |

### 生成ロジックの概要

1. 埋めにくい日(候補者に対して必要枠が多い日、例: 土日)から順に処理する
2. その日に働ける社員(曜日・希望休・週上限・連勤上限)を候補にする
3. 店舗ごとに、候補が少ない店舗から順に、NG店舗・必要レベル・距離上限を満たす社員をスコア順に配置する
   - スコア = −距離 + 希望店舗の加点 + 同じ店舗の継続加点 − 稼働率の偏り − 必要レベル超過分
   - リーダー要件がある店舗は、そのレベル以上の人を先に 1 名入れる
4. 同じ日の店舗間で担当を入れ替えて合計スコアが上がれば入れ替える
5. 人数不足・リーダー不在は警告として表示する

## シフト生成ツール(一店舗用)

https://mysbcafe-max.github.io/my-first-web-app/shift-single/

1 つの店舗の中で、**どの時間帯に誰を入れるか**を決めるためのツールです。登録したスタッフ情報(できる役割・レベル・この期間の出勤日数・勤務できる曜日・対応できる時間帯・希望休)と、店舗設定(シフトを作る期間・定休日・時間帯ごとの必要人数)から、期間内の日付 × 時間帯のアサイン表を作ります。

- データはブラウザ内(localStorage)にだけ保存され、外部サービスには送信しません(費用ゼロ)
- 勤務日数は**出勤日数でも公休日数でも**指定できます(スタッフごとに使い分け可)。公休で指定した場合は「期間の全日数 − 公休日数」が出勤日数になります
- **時短勤務**に対応。退勤する最遅時刻を登録すると、その人だけ実際の勤務時間で表示され、締め作業まで残れない人として扱われます
- 出勤時刻が決まっている人は**「この時刻で固定する」**を指定でき、その時刻に始まる時間帯にだけ入ります(例: 締め作業まで残れない時短スタッフを 09:30 固定にすると、早番にだけ入る)
- 人数は**「通常スタッフ 1・時短スタッフ 0.5」のカウント**で数えます。時間帯ごとの必要カウントに加えて、**1 日の合計カウントの下限**(例: 平日 4.5・土日祝 5)を指定できます
- **人手が足りないときは、平日の下限を自動で下げて全体を回します**(土日祝は下げません)。そのうえで、残っている出勤日数は人の少ない日に配るので、契約した出勤日数・公休日数を使い切れます
- 役割ごとの必須人数(フロア 1 人など)は**実人数**で確保します(時短でも 1 人として数える)
- 時間帯ごとに「役割ごとの必須人数」「必要なリーダーレベル」「平日/土日祝で必要カウントを変える」「開店準備・締め作業の有無」を設定できます
- **土日に加えて祝日も自動で「多めに配置する日」**として扱います。祝日は外部サービスを使わずに計算で判定します(振替休日・国民の休日を含む)。セール日などを「繁忙日」として個別に追加することもできます
- **締め作業がある枠には、締めの時間まで居られて担当できる人を必ず 1 人入れます**(時短スタッフを入れた日も、別途締め作業ができる人が確保されます)
- 結果は CSV(日付別・スタッフ別)で書き出せ、印刷にも対応しています
- 「データ」タブのサンプルで動作を試せます

### 業態にあわせたカスタマイズ

「役割(担当)」は店舗ごとに自由に定義できます。レベルの呼び方(1〜5)も店舗の言い方に変えられます。

| 業態 | 役割の例 |
|---|---|
| au ショップ・携帯ショップ | フロア(受付・整理券)/ カウンター(契約対応)/ 事務 |
| 飲食店・カフェ | ホール / キッチン |
| 小売・アパレル | レジ / 売場 |
| 役割を分けない | (役割なし。誰でもどの枠にも入れる) |

「店舗設定」タブの業態ひな形を選んで適用すると、役割・レベルの呼び方・時間帯をまとめて差し替えられます。役割の追加・名前変更・削除も自由にできます。

au ショップのひな形は、営業 10:00〜19:00 の前後 30 分を開店準備・締め作業の時間とみなし、
C(早番) 09:30〜18:30(開店準備あり)/ B(遅番) 10:30〜19:30(締め作業あり)の 2 枠を用意しています。

### 店舗に試用してもらうとき

店舗に渡す URL は次の 2 つです。

| 用途 | URL |
|---|---|
| 最初に読んでもらう案内 | https://mysbcafe-max.github.io/my-first-web-app/shift-single/guide.html |
| ツール本体(ブックマーク用) | https://mysbcafe-max.github.io/my-first-web-app/shift-single/ |

試用期間の案内を出すには、`shift-single/trial.js` の 3 行を書き換えます。

```js
storeName: 'au ショップ 〇〇店',   // 店舗名
startDate: '2026-09-15',          // 試用開始日(ここを入れると案内が出る)
contact: 'shift@example.com',     // 困ったときの連絡先
```

終了日は「開始日 + `months`(既定 3)か月 の前日」で自動計算され、案内・ツール画面の上に
「試用期間中(残り○日)」と表示されます。終了 14 日前から色が変わり、終了後は終了した旨を表示します。
**試用期間が過ぎてもツールが使えなくなることはありません**(機能制限はかけていません)。

データはブラウザ内にしか無いため、1 週間以上バックアップしていないと画面上部で書き出しをうながします。

### 生成ロジックの概要

1. 土日祝・繁忙日は「多めに配置する日」として必要カウントを切り替える
2. 埋めにくい日(候補者に対して必要枠が多い日)から順に処理する
3. 各時間帯で、役割ごとの必須人数を優先して、候補が少ない役割から埋める
4. リーダー要件がある枠は、そのレベル以上の人を先に 1 名入れる
5. 開店準備・締め作業がある枠は、その時間まで居られて担当できる人を先に 1 名入れる
6. 出勤日数の残りが多い人ほど優先し、いつもと同じ時間帯・連勤の少なさも考慮してスコアで選ぶ
7. 時間帯ごとの必要カウントを満たしたあと、1 日の合計カウントが下限に届くまで足す。端数(0.5)は時短スタッフで埋め、余分に人を使わない
8. 同じ日の時間帯どうしで担当を入れ替えて、埋められる不足があれば埋める(リーダー・締め・開店の担保は壊さない)
9. 足りない日が出たら、平日の下限を 0.5 ずつ必要な日数だけ下げて組み直す(土日祝は下げない)
10. 必要量を満たしたあと、残っている出勤日数を人の少ない日に配る(設定どおりの必要量は超えない)
11. カウント不足・リーダー不在・締め作業の担当なし・勤務日数の未達は警告として表示する
