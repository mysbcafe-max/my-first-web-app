## シフト自動生成ツール

https://mysbcafe-max.github.io/my-first-web-app/shift/

受注した案件(期間つき)と登録したスタッフ情報から、期間内の各日の現場アサイン表を作ります。

- **案件は期間指定で登録**します(例: 4〜5日間)。受注のたびに案件を追加してください。期間を空欄にすると常設の現場として扱われます
- **平均必要レベル**を案件ごとに設定できます。その日に入るスタッフのレベル平均がこの値以上になるよう調整します(小数可、例: 2.5)
- **案件ごとに顔ぶれが変わりにくい**よう、先にコアメンバーを決めてから日々を埋めます。希望休などで入れない日だけ交代要員が入り、翌日は元の担当に戻ります
- データはブラウザ内(localStorage)にだけ保存され、外部サービスには送信しません(費用ゼロ)
- 住所は都道府県・市区町村から距離を推定します。緯度・経度を入れると実距離で計算します
- レベル 1〜5 の呼び名(役職名)は「データ」タブから社内の呼び方に変更できます
- 結果は CSV(表形式・一覧)で書き出し、印刷もできます
- 「データ」タブの「サンプルを読み込む」で、期間つき案件を含むテストデータ(スタッフ 12 名・案件 6 件)が入ります

### 登録する項目

| 案件 | スタッフ |
|---|---|
| 案件名 / 現場の住所(緯度経度は任意) | 名前 / 住所(緯度経度は任意) |
| 期間(開始日〜終了日。空欄で常設) | レベル(1〜5) |
| 1日の必要人数 | 週の上限日数 |
| 平均必要レベル(0 で不問) | 勤務可能な曜日 |
| 最低レベル / リーダー要件 | 希望休 |
| 稼働曜日 | NG案件 / 希望案件 |

ファイル構成:

| ファイル | 役割 |
|---|---|
| `shift/index.html` | 画面 |
| `shift/style.css` | スタイル |
| `shift/app.js` | 画面の処理(保存・フォーム・結果表示) |
| `shift/scheduler.js` | 生成ロジック(UI に依存しない) |
| `shift/test/` | ロジックのテスト(`node --test "shift/test/*.test.js"`) |

### 生成ロジックの概要

**1. コアメンバーの選定(顔ぶれを固定する土台)**

案件ごとに、必要人数ぶんの「コアメンバー」を先に決めます。

- 期間を通して入れる人(勤務可能曜日・希望休・週の上限に照らして全日入れる人)を優先します。足りないときだけ、一部しか入れない人を候補に含めます
- 期間が重なる案件のコアには同じ人を入れません(同じ日に 2 現場は不可のため)
- 週の上限も先取りして計算します。日付が重ならなくても同じ週に収まらない案件には、同じ人を選びません
- 平均必要レベル・リーダー要件を満たすよう入れ替えます
- 距離が近い人・希望案件・仕事が偏っていない人を優先し、高レベルの人は要求の高い案件のために温存します

**2. 日ごとの割り当て**

1. コアメンバーのうち、その日働ける人を入れる
2. 足りない分を交代要員で埋める(その案件に入った実績がある人を優先)
3. 平均必要レベルを下回る場合、レベルの低い人を高い人と入れ替える
4. 同じ日の案件間で担当を入れ替えて合計スコアが上がれば入れ替える(コアメンバーは動かさない)

**3. 修復パス**

空き枠が残ったら、週の上限を使い切った人の別の日を他の人に肩代わりしてもらう連鎖(増加路)を探して埋めます。

**4. 警告**

人数不足・平均レベル不足・リーダー不在を警告として表示します。

### 守る条件

絶対に破らない条件(ハード制約): NG案件・最低レベル・通勤距離の上限・勤務可能曜日・希望休・週の上限日数・連勤上限・同じ日に 2 現場に入らないこと・案件の期間と稼働曜日。

平均必要レベルは満たすよう調整しますが、どうしても満たせない場合は人を配置したうえで警告を出します(現場に人がいない方が困るため)。
